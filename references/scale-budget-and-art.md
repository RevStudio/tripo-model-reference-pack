# 게임 크기·버텍스 예산·아트 프리셋 예시

## 크기의 의미부터 구분

- W(X)×D(Y)×H(Z)를 게임 cm로 기록한다. 원래 디자인 치수, 게임 적용 치수, 변환 배율은 서로 다른 필드다.
- 사용자 승인 치수가 있으면 그대로 사용한다. 현재 단위가 게임 cm인지 확인하지 않고 다시 축소하지 않는다.
- 피벗은 식물의 줄기 바닥, 가구의 접지 중심 등 실제 배치 기준으로 명시한다. 다리는 상판 보행 높이와 양 끝 연결점, 건물은 바닥과 출입구 유효 높이를 별도로 기록한다.
- 문/회전 부품이 필요하면 본체와 별도 오브젝트, 경첩 위치·축·열림 방향·주변 여유를 요구한다. 이미지 패키지만으로 여닫는 동작이 구현되었다고 하지 않는다.

### 프로젝트 프리셋 예시 (자기 프로젝트 값으로 바꿔 쓴다)

아래는 프리셋을 적는 방법을 보여 주는 예시다. 플레이어 스프라이트가 작은 HD-2D 프로젝트에서 쓴 값이며, 다른 프로젝트에 그대로 적용하지 않는다.

기준은 **88cm 플레이어**다. 이 예시 프로젝트의 디자인 환산 관례는 디자인 1m → 게임 45cm(0.45 아트 스케일)였으며, 일반적인 m→cm 단위 변환과 다르다. 이미 정해진 게임 cm 수치에는 재적용하지 않는다. 새로운 프로젝트에는 88cm/0.45를 자동 적용하지 않는다.

승인 예시는 큰 나무 300×250×420cm와 작은 나무 170×150×320cm다. 이는 모든 나무의 고정 규격이 아니라 기존 맵 크기와 대비를 유지하기 위한 해당 에셋 명세다. 모델 이름이나 플레이어 크기가 달라지면 맥락을 다시 확인한다.

## 예산은 목표이며 측정 결과가 아니다

문서와 CSV에서 다음을 분리한다.

- 원본 V: 불필요한 중복이 제거된 소스 메시의 버텍스 수 목표.
- Q: Quad 면 수 목표. Tripo가 이 값을 보장하거나 자동으로 all-quad를 만든다고 가정하지 않는다.
- T: 게임 렌더용 삼각형 수 목표 상한. Quad와 삼각형만 있으면 T = 2Q + 원래 삼각형 수이며, n-gon은 별도 계산이 필요하다.
- 엔진 render V: UV 경계·하드 노멀 등 분리로 원본 V보다 커질 수 있다. 이미지에서 산출할 수 없다.

V만으로 Q/T를 추정하거나 네이티브 생성 결과가 예산을 만족했다고 쓰지 않는다. Q 범위 상한을 설정했다면 남는 삼각형까지 고려해 T 상한과 모순되지 않는지 확인한다. 양면 머티리얼은 메시 면 수와 별개로 픽셀 처리 비용에 영향을 줄 수 있다.

### 규모가 비슷한 게임 환경 소품의 출발 범위

아래는 이 워크플로의 **초기 설계 제안**이지 Tripo 제한이나 성능 인증 수치가 아니다. 화면 점유율, 고유 모델 수, 반복 배치 밀도, 실루엣과 기능을 보고 조정한다. 원본이 있으면 측정치를 별도로 표시한다.

| 유형 | 원본 V 목표 | Q 목표 | 게임 T 상한 목표 |
| --- | ---: | ---: | ---: |
| 작은 단순 소품 | 80–400 | 60–320 | 800 |
| 작은 풀·꽃 군락 | 180–550 | 150–450 | 1,100 |
| 단순한 입체 수관 나무 | 400–1,100 | 330–950 | 2,200 |
| 짧은 저폴리 목재 다리 | 900–1,600 | 750–1,350 | 3,200 |
| 단순 소형 건물 외관 | 1,200–3,000 | 1,000–2,500 | 6,000 |

모델별로 넓은 범위를 좁히고 예산의 근거를 한 문장으로 적는다. 큰 모델·특수 형태에 이 표의 상한을 강제하지 않는다. 정적인 좌우 대칭 부품은 복제/미러 제작을 제안할 수 있지만, 자연물의 변형이나 비대칭 외형을 예산만을 위해 제거하지 않는다. UV 미러링은 글자·방향성 무늬·오염 비대칭에 영향을 주므로 별도 선택이다.

Quad 유지 원본을 기본으로 요청한다. 반환 요청은 .blend 또는 Quad가 보존된 FBX/OBJ와 실제 V/Q/T 수로 한다. GLB만으로 Quad 보존을 확인할 수 없다. 기존 삼각형을 감추거나 요청 없이 all-quad 보존을 약속하지 않는다.

## 표면 프리셋 예시: 현대 HD2D

Octopath Traveler 계열의 깨끗한 현대 HD2D 감성을 목표로 할 때 사용한다. 다른 아트 지시가 있으면 대체한다.

    Clean modern HD2D game-environment texture treatment: intentional small pixel
    clusters and crisp painted material marks, rich connected color ramps,
    readable midtones, warm highlights and cooler hue-shifted shadows.
    Detailed surface color on SIMPLE low-poly geometry, not extra geometry.
    No CRT scanlines, forced four/eight-color palette, coarse posterization,
    dithering noise, giant mosaic blocks, muddy black shadows or washed-out haze.

나무는 수관의 큰 입체 명암을 유지하고 잎 무리는 작은 색 클러스터로 처리한다. 잎 하나하나를 전부 모델링하거나 수관 전체를 납작한 카드로 바꾸지 않는다. 저폴리라는 이유로 측면 깊이를 희생하지 않는다.

모델당 BaseColor 권장 시작 해상도는 작은 군락 512–1024, 중간 소품·나무 1024, 큰 건물/근접 소품 1024–2048 정도로 **제안**할 수 있다. 실제 UV, 화면 점유, 아틀라스 공유 여부를 보고 정하며 이를 이미지 생성 해상도와 혼동하지 않는다. 표면마다 픽셀 밀도가 지나치게 다르지 않게 요청한다.

대상 플랫폼(예: Windows 우선, 모바일 검토 예정)은 예산과 텍스처 선택의 참고다. 메시·LOD·오버드로·머티리얼·드로콜·실기기 성능 검수 전에는 모바일 대응 완료나 특정 FPS를 보증하지 않는다. 완성 스타일 참고를 실제 UV 텍스처로 착각하지 않도록 문서에 표시한다.
